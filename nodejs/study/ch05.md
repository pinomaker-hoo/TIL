# 5강. 이벤트 루프 실전 모의연습과 6단계 페이즈 완벽 마스터

## 개요

NodeJS의 심장인 libuv가 어떻게 거대한 시스템을 굴러가게 하는 지와 메모리/스레드 레벨에서 벌어지는 실제 동작 원리를 정리합니다.

- Single Thread, Call Stack, libuv, Event Queue, Event Loop

```
현업에서 API 응답 지연/CPU 100% 스파이크 현상이 발생했을 때 Call Stack이 막힌 것인지 Thread Pool이 고갈된 것인지 MicroTask Queue가 폭주하여 기아 현상(Starvation)이 발생한 것인지 판단하여 처리할 수 있어야한다.
```

## 현장을 굴러가게 만드는 4가지 핵심 부품

### Call Stack

단 하나의 작업 공간 V8엔진 내부에는 변수가 저장되는 창고 (Heap Memory)와 하나의 Call Stack(책상으로 비유)가 있습니다. 코드가 실행된다는 것은 책상에 서류가 들어왔다 즉 Call Stack에 작업이 할당됨을 의미합니다.

Call Stack은 후입선출(LIFO, Last In First Out) 구조를 가지고 있으며, 메인 스레드가 한 개이기에 해당 Stack에 큰 파일 읽기와 같은 작업이 할당되면 Blocking이 발생될 수 있습니다.

```
실무에선 재귀 함수를 잘못 작성하여 탈출 조건을 주지 않으면 함수가 Call Stack에 무한하게 쌓이다가 운영체제의 할당한 메모리를 넘기는 Maximum call stack size exceeded가 발생하여 서버가 크래시나게 됩니다.
```

```
=====================================================
[시각화] 동기식 작업 시 콜 스택의 블로킹 상태
=====================================================
const 도면 = fs.readFileSync('10GB_도면.txt');
console.log('완료');

[ Call Stack (소장님 책상) ]
  |                                   |
  | fs.readFileSync('10GB_도면.txt') | <-- 여기서 몇 분 동안 멈춤! (블로킹)
  | 메인 실행 컨텍스트                |
  -------------------------------------
  * 결과: 책상이 막혀 그 아래의 console.log는 아예 책상에 올라오지도 못함.
```

## libuv

libuv 내부에는 여러 스레드를 가져 파일 입출력, 암호화등을 병렬로 처리 가능한 쓰레드풀을 가지고 있는 C언어 기반의 라이브러리 입니다. 개발자가 코드를 짜는 환경은 Single Thread 이지만 시스템 밑바탕에선 libuv가 Multi Thread로 동작하게 됩니다.

```
libuv의 쓰레드풀은 기본적으로 4개지만, 상황에 따라 서버의 코어수에 맞춰 UV_THREADPOOL_SIZE를 튜닝하여 병목을 해소할 수 있습니다.
```

## Event Queue

Event Queue는 libuv에서 비동기 작업을 마친 후 작업이 완료됨에 따른 CallBack Function이 차례대로 대기하는 공간 입니다. Queue의 자료 구조이기에 선입선출(FIFO, First In First Out)에 따라 콜백 함수가 처리되며, 6개의 전용 큐로 분리되어 있고 Call Stack에 할당되는 우선순위가 다릅니다.

## Event Loop

Event Queue에 존재하는 콜백 함수들을 Call Stack으로 보낼 지 결정하는 감시 시스템으로, Call Stack이 완전히 비어있을 때만 작동합니다.

```
=====================================================
[시각화] 비동기 작업의 유기적 흐름 (Call Stack -> libuv -> Queue)
=====================================================
fs.readFile('도면.txt', (err, data) => console.log('다 읽음!'));

1. 지시 즉시 전달 (소장님은 바로 책상을 비움)
[ Call Stack ] : (텅 빔 - 다음 코드로 즉시 넘어감)
      ⬇️ (작업 위임)

2. 백그라운드 작업 (하청업체가 대신 일함)
[ libuv 스레드 풀 ] : [ 일꾼1: 도면.txt 읽는 중... ]
      ⬇️ (작업 완료)

3. 보고서 대기 (완성 순서대로 줄서기)
[ 이벤트 큐 ] : [ 콜백: console.log('다 읽음!') ] 대기 중!
      ⬇️ (순찰 반장: 콜 스택이 비어있는지 확인 후 밀어 올림)

4. 최종 처리
[ Call Stack ] : 콜백 함수 실행 -> 화면에 '다 읽음!' 출력
```

## 심층 해부: 이벤트 루프의 6단계 페이즈(Phases)

Event Loop는 하나의 Event Queue만 감시하는 것이 아닌 특정 작업의 독점을 막기 위해 분리된 총 6개의 Event Queue를 감시합니다.

- Timer (타이머 정거장):setTimeout, setInterval 등 약속된 시간이 지난 알람 콜백들을 처리합니다. (💡 강사 팁: setTimeout(0)이라고 적어도 운영체제 타이머의 물리적 한계로 인해 정확히 0ms 만에 실행됨을 보장하지는 않습니다. 보통 최소 1ms 이상의 지연이 발생합니다.)

- Pending Callbacks (대기 정거장): TCP 오류 등 운영체제 레벨의 긴급한 에러를 처리합니다.

- Idle, Prepare (유휴 정거장): 내부 정비 시간 (개발자 코드 실행 안 됨).

- Poll (폴 / 핵심 대기 정거장): 가장 중요하고 바쁜 정거장. 파일 읽기, 데이터베이스 응답 등 대부분의 I/O 콜백이 이곳에 모입니다. 당장 처리할 일이 없으면 버스 시동을 켜둔 채 새 일거리가 올 때까지 여기서 대기합니다.

- Check (체크 정거장):setImmediate() 전용 창구입니다.

- Close Callbacks (종료 정거장): 소켓 연결 종료 등 메모리 누수를 막기 위한 뒷정리를 담당합니다.

### NextTick Queue, MicroTask Queue

위의 6개의 Queue와 별개로 가장 우선 순위가 높은 NextTick Queue와 MicroTask Queue가 존재한다. 2개의 큐에 콜백 함수가 담어져있을 경우 위의 이벤트 루피의 6개의 페이지에서 어떤 페이즈에 있던 2개의 큐에 있는 콜백을 우선 처리하게된다.

```
=====================================================
[시각화] 정거장 이동 중 VIP 새치기 발생의 순간
=====================================================
setTimeout(() => {
    console.log('1. 알람 처리 중...');
    Promise.resolve().then(() => console.log('2. [새치기] 긴급 프로미스 생성!'));
}, 0);

[ 일반 1번 정거장 (Timer) 처리 완료 직후의 순간 ]
--------------------------------------------------
[ Call Stack ] : (알람 처리 완료로 텅 빔)

[ VIP 결재함 (Promise) ] : [ '2. [새치기] 긴급 프로미스 생성!' ] <-- 방금 접수됨!

[ 일반 2번 정거장 (Pending) ] : (여기로 넘어가야 하지만...)

▶ 이벤트 루프의 행동:
"잠깐! 2번 정거장으로 가기 전에 VIP 함에 서류가 있네? 무조건 저것부터 콜 스택으로 올려!"
결과적으로 2번 정거장으로 가기 전, Promise가 중간에 가로채어 실행됩니다.
```

아래 샘플 코드의 실행 구조이다.

```typescript
console.log("A: 현장 출근 (동기)");
setTimeout(() => console.log("B: 알람 (Timer 정거장)"), 0);
Promise.resolve().then(() => console.log("C: VIP 결재 (Promise)"));
console.log("D: 현장 퇴근 (동기)");
```

```[Step 1] 동기 코드 즉시 실행
-----------------------------------------------------
▶ 출력: "A: 현장 출근"
[ Call Stack ] : console.log("A") 실행 후 즉시 비워짐.
[ VIP 결재함 ] : (비어 있음)
[ 일반 1번 정거장 ] : (비어 있음)

[Step 2] setTimeout과 Promise 등록
-----------------------------------------------------
* 소장님이 지시만 내리고 책상을 즉시 치웁니다.
[ Call Stack ] : (비어 있음)
[ VIP 결재함 ] : [ "C: VIP 결재" ] <-- 우선순위 높은 Promise 대기
[ 일반 1번 정거장 ] : [ "B: 알람" ] <-- 0초 뒤 실행 예약 대기

[Step 3] 마지막 동기 코드 실행 및 콜 스택 비워짐
-----------------------------------------------------
▶ 출력: "D: 현장 퇴근"
[ Call Stack ] : console.log("D") 실행 후 완전히 텅 빔!
* 소장님 책상이 텅 빈 이 순간, 이벤트 루프(순찰 반장)가 움직입니다.

[Step 4] 이벤트 루프의 개입 (무조건 VIP 먼저!)
-----------------------------------------------------
* 이벤트 루프는 일반 정거장에 일이 있어도, 무조건 VIP 결재함부터 열어서 올립니다.
▶ 출력: "C: VIP 결재"
[ Call Stack ] : (VIP 서류 처리 후 비워짐)
[ VIP 결재함 ] : (완전히 텅 빔!)
[ 일반 1번 정거장 ] : [ "B: 알람" ] <-- 여전히 대기 중

[Step 5] 일반 정거장 처리 (마무리)
-----------------------------------------------------
* VIP 결재함이 비워진 것을 확인하고 나서야 일반 1번 정거장으로 버스가 향합니다.
▶ 출력: "B: 알람"
[ Call Stack ] : (일반 서류 처리 완료)
[ VIP 결재함 ] : (비어 있음)
[ 일반 1번 정거장 ] : (비어 있음)

최종 출력 순서: A -> D -> C -> B
```
