# AI 컨텍스트와 컨텍스트 엔지니어링

## 개요

AI 컨텍스트(Context)는 LLM이 **현재 답을 만들 때 실제로 볼 수 있는 정보 전체**이다. 모델이 과거에 학습한 지식과는 다르며, 요청할 때마다 컨텍스트 윈도우 안에 들어온 정보만 현재 작업의 직접적인 근거가 된다.

> 좋은 답을 얻으려면 질문만 잘 쓰는 것이 아니라, 모델이 판단에 필요한 정보를 적절한 시점에 볼 수 있게 해야 한다.

<br />

---

## 1. 컨텍스트에는 무엇이 들어가는가

일반적인 AI 애플리케이션의 컨텍스트는 다음 요소로 구성된다.

| 구성 요소 | 예시 |
| --- | --- |
| 시스템 지시 | 역할, 금지 사항, 답변 형식 |
| 사용자 요청 | 지금 해결해야 할 질문이나 목표 |
| 대화 기록 | 이전 질문, 답변, 결정 사항 |
| 외부 지식 | RAG로 검색한 문서, DB 조회 결과 |
| 도구 정보 | 사용할 수 있는 함수와 각 함수의 설명 |
| 도구 실행 결과 | API 응답, 파일 내용, 테스트 결과 |
| 작업 상태 | 계획, 완료한 일, 남은 일, 메모리 |

이 정보들은 모두 토큰으로 변환되어 유한한 **컨텍스트 윈도우**를 사용한다. 따라서 정보를 많이 넣는다고 항상 좋아지는 것은 아니다. 관련 없는 내용이 많아지면 비용과 지연 시간이 늘고, 중요한 지시가 묻혀 답변 품질도 낮아질 수 있다.

<br />

## 2. 프롬프트와 컨텍스트의 차이

프롬프트는 모델에게 전달하는 **지시문**에 가깝고, 컨텍스트는 모델이 현재 추론에 사용하는 **입력 환경 전체**이다.

```text
프롬프트 엔지니어링
└── 지시를 어떤 문장과 구조로 쓸 것인가?

컨텍스트 엔지니어링
└── 지금 어떤 지시, 기록, 문서, 도구 결과를 모델에게 보여줄 것인가?
```

예를 들어 고객 문의에 답하는 AI라면 "친절하게 답하라"는 프롬프트만으로는 부족하다. 고객의 주문 내역, 최신 환불 정책, 이전 상담 기록을 함께 제공해야 정확한 답을 만들 수 있다.

<br />

## 3. 컨텍스트 엔지니어링이란

컨텍스트 엔지니어링(Context Engineering)은 원하는 결과가 나올 가능성을 높이기 위해 **컨텍스트 윈도우에 들어갈 정보를 선택하고, 구성하고, 갱신하는 작업**이다.

핵심 목표는 "최대한 많은 정보"가 아니라 **가장 적은 고품질 정보**를 제공하는 것이다.

주요 기법은 다음과 같다.

### (1) 검색 — 필요한 순간에 가져오기

모든 문서를 미리 넣지 않고 RAG, 파일 검색, DB 조회 등을 이용해 현재 작업에 관련된 정보만 가져온다.

### (2) 선택 — 불필요한 정보 제거하기

권한, 최신성, 관련도를 기준으로 검색 결과를 필터링하고 중복 내용을 제거한다. 도구도 작업에 필요한 것만 노출하는 편이 선택 오류를 줄인다.

### (3) 압축 — 긴 기록을 요약하기

대화나 작업이 길어지면 오래된 내용을 요약하되, 요구사항·결정·오류·남은 작업 같은 핵심 상태는 보존한다.

### (4) 격리 — 작업별로 컨텍스트 나누기

큰 작업을 하위 작업으로 나누고 각 작업에 필요한 정보만 제공한다. 하위 에이전트나 별도 세션을 쓰는 것도 한 방법이다.

### (5) 영속화 — 컨텍스트 밖에 기록하기

컨텍스트 윈도우는 영구 메모리가 아니다. 중요한 결정과 진행 상태는 문서, DB, 체크포인트 같은 외부 저장소에 남겨 다음 실행에서 다시 읽을 수 있게 한다.

<br />

## 4. 간단한 예시

```text
[나쁜 구성]
전체 사내 문서 500개 + 전체 대화 기록 + 사용자 질문
→ 중요한 정보가 묻히고 비용이 커짐

[좋은 구성]
시스템 규칙
+ 사용자 질문
+ 해당 사용자의 주문 정보
+ 최신 환불 정책 중 관련 문단 3개
+ 직전 상담의 핵심 요약
→ 작고 관련성 높은 컨텍스트
```

<br />

## 5. 실무 체크리스트

- 모델이 답을 내리는 데 꼭 필요한 정보인가?
- 정보가 최신이며 신뢰할 수 있는가?
- 서로 충돌하는 지시의 우선순위가 명확한가?
- 긴 원문 대신 필요한 부분만 검색하거나 요약했는가?
- 비밀번호나 개인정보처럼 모델이 볼 필요 없는 정보가 포함되지 않았는가?
- 컨텍스트가 잘렸을 때도 핵심 작업 상태를 복구할 수 있는가?

<br />

## 6. 다른 개념과의 관계

```text
RAG                 필요한 외부 지식을 검색한다
        ↓
컨텍스트 엔지니어링  검색 결과·지시·기록·도구 정보를 조립한다
        ↓
AI 에이전트          조립된 컨텍스트를 보고 다음 행동을 결정한다
```

RAG는 컨텍스트를 채우는 방법 중 하나이고, 컨텍스트 엔지니어링은 그보다 넓은 개념이다. 에이전트는 여러 단계에 걸쳐 행동하므로 매 단계마다 늘어나는 기록과 도구 결과를 관리해야 한다.
