# Array / List / Tuple

## 개요

배열(Array), 리스트(List), 튜플(Tuple)은 모두 "여러 데이터를 순서 있게 담는" 자료구조지만, 언어마다 부르는 이름과 실제 동작이 달라 혼동하기 쉽다. 이 문서에서는 자료구조 관점의 정의를 먼저 잡고, JavaScript/TypeScript, Python, Java에서 각각 어떻게 구현되어 있는지 정리한다.

- Array : 같은 타입의 데이터를 메모리에 연속으로 배치한 고정 크기 구조
- List : 크기가 동적으로 변하는 순서 있는 컬렉션 (ADT 관점의 개념)
- Tuple : 한 번 만들면 바꿀 수 없는(immutable), 서로 다른 타입을 담을 수 있는 고정 크기 묶음

## Array (배열)

전통적인 의미의 배열은 "같은 타입의 요소를 메모리에 연속으로 배치한 고정 크기 구조"다. 시작 주소와 요소 크기만 알면 `시작 주소 + (index × 요소 크기)`라는 단순한 산수로 어떤 요소든 즉시 접근할 수 있다. 배열의 Index 접근이 O(1)인 이유가 바로 이것이다.

```
=====================================================
[시각화] 배열의 메모리 배치 (int 4byte 기준)
=====================================================

 주소 :  0x100   0x104   0x108   0x10C
        -----------------------------
 값   : |  10  |  20  |  30  |  40  |
        -----------------------------
 index:    0       1       2       3

* arr[2]의 주소 = 0x100 + (2 x 4byte) = 0x108, 순회 없이 즉시 계산된다.
* 연속 배치 덕분에 CPU 캐시에 인접 요소가 함께 올라와(캐시 지역성) 순회도 매우 빠르다.
```

| 연산                | 시간 복잡도 | 이유                                    |
| ------------------- | ----------- | --------------------------------------- |
| Index 접근/수정     | O(1)        | 주소 계산만 하면 됨                     |
| 맨 뒤 삽입/삭제     | O(1)*       | 뒤 공간에 넣기만 하면 됨                |
| 맨 앞/중간 삽입/삭제 | O(n)        | 뒤의 요소를 전부 밀거나 당겨야 함       |
| 탐색 (값으로)       | O(n)        | 앞에서부터 하나씩 확인                  |

\* 동적 배열에서 용량이 가득 찼을 때는 재할당이 일어나 O(n)이지만, 분할 상환 관점에서는 O(1)이다.

### 정적 배열 vs 동적 배열

C의 `int arr[10]`처럼 크기가 고정된 것이 정적 배열이다. 하지만 실무에서 크기를 미리 아는 경우는 드물기 때문에, 대부분의 언어는 꽉 차면 더 큰 배열을 새로 할당하고 기존 요소를 복사하는 동적 배열(Dynamic Array)을 제공한다.

```
=====================================================
[시각화] 동적 배열의 확장 (보통 1.5~2배씩 성장)
=====================================================

 용량 4가 가득 찬 상태에서 50 삽입

 [ 10 | 20 | 30 | 40 ]          <-- 가득 참
          |
          v  용량 8짜리 새 배열 할당 + 전체 복사 O(n)
 [ 10 | 20 | 30 | 40 | 50 |  |  |  ]

* 확장은 가끔만 일어나므로 push의 비용은 분할 상환 O(1)로 취급한다.
* Java ArrayList, Python list, C++ vector, JS Array 모두 이 구조다.
```

## List (리스트)

자료구조 이론에서 List는 "순서가 있고 크기가 변할 수 있는 컬렉션"이라는 추상 자료형(ADT)이다. 즉 List는 인터페이스고, 그것을 무엇으로 구현하느냐에 따라 두 갈래로 나뉜다.

1. ArrayList (동적 배열 기반) : Index 접근 O(1), 중간 삽입/삭제 O(n)
2. LinkedList (연결 리스트 기반) : Index 접근 O(n), Node 참조가 있으면 삽입/삭제 O(1) ([linked-list.md](./linked-list.md) 참고)

Java에서는 이 구분이 명시적이다.

```java
List<Integer> arrayList = new ArrayList<>();   // 동적 배열 기반
List<Integer> linkedList = new LinkedList<>(); // 이중 연결 리스트 기반
```

```
"삽입/삭제가 많으면 LinkedList"라고 외우기 쉽지만, 실제 벤치마크에서는
캐시 지역성 때문에 대부분의 시나리오에서 ArrayList가 빠르다.
Java의 창시자 Joshua Bloch조차 "LinkedList를 쓸 일이 거의 없다"고 말했을 정도로,
기본 선택은 ArrayList이고 LinkedList는 Deque처럼 양 끝 조작이 핵심일 때만 고려한다.
```

## Tuple (튜플)

Tuple은 "생성 후 변경할 수 없고(immutable), 서로 다른 타입을 담을 수 있는 고정 크기 묶음"이다. List가 "동질적인 데이터의 가변 목록"이라면, Tuple은 "이질적인 값들의 불변 묶음"으로 좌표 (x, y), (성공 여부, 결과값) 같은 레코드성 데이터에 쓰인다.

### Python의 Tuple

Python은 Tuple이 언어 차원의 일급 개념이다.

```python
point = (3, 5)          # 튜플 생성
x, y = point            # 구조 분해 (unpacking)

point[0] = 10           # TypeError! 튜플은 불변이다

# 불변이기 때문에 hash가 가능해서 dict의 key로 쓸 수 있다 (list는 불가능)
visited = {(0, 0): True, (1, 2): True}

# 함수의 다중 리턴도 사실 튜플이다
def divide(a, b):
    return a // b, a % b   # (몫, 나머지) 튜플 리턴
```

불변이라는 제약 덕분에 얻는 것이 명확하다. Hashable이라 dict의 Key나 set의 원소로 쓸 수 있고, 어디서도 수정될 수 없다는 보장 덕분에 여러 곳에 안심하고 공유할 수 있다.

### TypeScript의 Tuple

TypeScript의 Tuple은 "각 위치의 타입과 길이가 고정된 배열"이라는 타입 시스템 차원의 개념이다. 런타임에는 그냥 JavaScript 배열이라 Python처럼 불변이 아니며, 불변까지 원하면 `readonly`를 붙여야 한다.

```typescript
// [문자열, 숫자] 순서와 길이가 타입으로 고정된다
const user: [string, number] = ["pino", 28];

const wrong: [string, number] = [28, "pino"]; // 컴파일 에러!

// 불변으로 만들려면 readonly
const point: readonly [number, number] = [3, 5];
// point[0] = 10; // 컴파일 에러!

// React의 useState가 튜플을 리턴하는 대표적인 예다
// const [count, setCount] = useState(0);  --> [값, setter 함수] 튜플
```

React의 `useState`가 객체가 아닌 Tuple을 리턴하는 이유는, 구조 분해 시 사용자가 원하는 이름(`count`, `setCount`)을 자유롭게 붙일 수 있게 하기 위해서다. 객체였다면 정해진 프로퍼티 이름을 써야 했을 것이다.

## JavaScript의 Array는 사실 배열이 아니다?

JavaScript의 Array는 전통적 배열과 달리 타입이 섞일 수 있고 크기도 자유로운 특이한 존재다. 명세상으로는 "숫자 Key를 가진 특수한 객체"이지만, V8 엔진은 성능을 위해 내부적으로 요소 종류(elements kind)에 따라 실제 메모리 구조를 바꾼다.

1. PACKED_SMI_ELEMENTS : 작은 정수만 있으면 진짜 C 배열처럼 연속 메모리에 저장 (가장 빠름)
2. PACKED_DOUBLE_ELEMENTS : 실수가 섞이면 double 배열로 전환
3. PACKED_ELEMENTS : 문자열/객체가 섞이면 포인터 배열로 전환
4. DICTIONARY_ELEMENTS : 중간이 뻥 뚫린 희소 배열이 되면 Hash Table 모드로 전환 (가장 느림)

한 번 느슨한 쪽으로 전환되면 다시 되돌아가지 않는다(단방향 전환).

```
성능이 중요한 코드에서는 배열에 타입을 섞지 않고, new Array(1000)처럼 구멍 난 배열을 만들거나
arr[10000] = 1 처럼 Index를 건너뛰어 할당하는 것을 피해야 한다.
희소 배열이 되는 순간 V8이 Hash Table 모드로 강등시켜 순회 성능이 크게 떨어진다.
숫자 연산이 핵심이라면 처음부터 연속 메모리가 보장되는 TypedArray(Float64Array 등)를 쓰는 것이 낫다.
```

## 언어별 명칭 정리

같은 개념이 언어마다 다른 이름으로 불리는 것을 표로 정리하면 아래와 같다.

| 개념                  | JavaScript/TS         | Python  | Java            |
| --------------------- | --------------------- | ------- | --------------- |
| 동적 배열 (가변 목록) | Array (`[]`)          | list    | ArrayList       |
| 고정 크기 원시 배열   | TypedArray            | array 모듈 | `int[]` 배열 |
| 연결 리스트           | (직접 구현)           | (직접 구현) | LinkedList  |
| 튜플 (불변 묶음)      | Tuple 타입 (`readonly [A, B]`) | tuple | record (14+) |

<br />

## 무엇을 언제 쓸까

1. 같은 성격의 데이터 목록을 다룬다 → 동적 배열 (JS Array, Python list). 고민 없이 기본 선택지다.
2. 서로 다른 타입의 값을 하나로 묶어 리턴/전달한다 → Tuple. "이 묶음은 구조가 고정"이라는 의도가 드러난다.
3. dict/set의 Key로 좌표 같은 복합 값을 쓴다 → 불변인 Tuple만 가능하다 (Python).
4. 대량의 숫자 연산 → TypedArray(JS), numpy array(Python)처럼 연속 메모리가 보장되는 진짜 배열.
5. 양 끝 삽입/삭제가 핵심 → Deque (Linked List 또는 원형 버퍼 기반).

<br />

## 정리

1. Array는 연속 메모리 + Index 산술 덕분에 O(1) 접근과 뛰어난 캐시 지역성을 갖지만, 중간 삽입/삭제는 O(n)이다.
2. List는 "순서 있는 가변 컬렉션"이라는 추상 개념이며, ArrayList(동적 배열)와 LinkedList 두 구현이 있고 기본 선택은 ArrayList다.
3. Tuple은 불변 + 이질적 타입 + 고정 크기 묶음으로, Python에서는 hashable이라 dict Key로 쓸 수 있고 TypeScript에서는 위치별 타입을 고정하는 타입 개념이다.
4. JavaScript의 Array는 V8이 요소 종류에 따라 진짜 배열과 Hash Table 사이를 오가므로, 타입 섞기와 희소 배열을 피해야 성능이 유지된다.
