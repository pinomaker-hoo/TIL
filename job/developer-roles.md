# 개발자 직무의 종류

## 개요

개발 조직에는 코드를 작성하는 소프트웨어 엔지니어뿐 아니라 고객의 문제를 기술로 해결하는 FDE, 시스템 도입을 설계하는 SA, 데이터를 안정적으로 관리하는 DBA 등 다양한 직무가 있다.

같은 직무명이라도 회사마다 담당 범위가 다르므로 채용 공고를 볼 때는 **직무명보다 실제 업무와 책임 범위**를 확인해야 한다.

---

## 1. 제품을 개발하는 직무

### 프론트엔드 개발자 (Frontend Engineer)

사용자가 웹 브라우저에서 직접 접하는 화면과 상호작용을 구현한다.

- UI 컴포넌트와 페이지 개발
- 서버 API 연동 및 클라이언트 상태 관리
- 접근성, 반응형 화면, 브라우저 호환성 대응
- 렌더링 속도와 사용자 경험 개선

HTML, CSS, JavaScript 또는 TypeScript가 기본이며 React, Vue, Angular 같은 프레임워크를 주로 사용한다.

### 백엔드 개발자 (Backend Engineer)

서비스의 비즈니스 로직, API, 데이터 처리와 서버 시스템을 개발한다.

- API와 비즈니스 로직 설계
- 데이터베이스 모델링과 트랜잭션 처리
- 인증·인가, 외부 시스템 연동
- 성능, 보안, 장애 대응

Java, Kotlin, JavaScript 또는 TypeScript, Python, Go 등과 데이터베이스, 네트워크, 운영체제에 대한 이해가 필요하다.

### 풀스택 개발자 (Full-stack Engineer)

프론트엔드와 백엔드를 모두 다룬다. 작은 팀에서는 제품 전체를 빠르게 구현하는 역할을 맡고, 큰 조직에서는 한쪽 영역을 주력으로 하면서 다른 영역까지 담당하는 경우가 많다.

풀스택은 모든 분야의 전문가라는 뜻보다 **제품의 한 기능을 처음부터 끝까지 완성할 수 있는 개발자**에 가깝다.

### 모바일 앱 개발자 (Mobile Engineer)

iOS 또는 Android 애플리케이션을 개발한다.

- Swift와 SwiftUI를 사용하는 iOS 개발
- Kotlin과 Jetpack Compose를 사용하는 Android 개발
- Flutter, React Native 등을 이용한 크로스 플랫폼 개발
- 앱 성능, 배터리, 배포 심사, 기기별 호환성 관리

### 임베디드·펌웨어 개발자 (Embedded/Firmware Engineer)

가전, 자동차, 로봇, 반도체 장비와 같은 하드웨어 내부의 소프트웨어를 개발한다. 제한된 CPU와 메모리 환경, 실시간 처리, 하드웨어 제어가 중요한 분야다.

주로 C, C++, Rust, RTOS와 전자회로 및 통신 프로토콜 지식이 활용된다.

### 게임 개발자 (Game Developer)

게임 클라이언트, 게임 서버, 그래픽스, 엔진, 콘텐츠 도구 등을 개발한다. Unity와 C#, Unreal Engine과 C++ 등이 대표적인 기술 조합이다.

## 2. 데이터와 인공지능 직무

### 데이터 엔지니어 (Data Engineer)

여러 시스템의 데이터를 수집·정제·저장하고, 분석이나 AI 학습에 사용할 수 있는 데이터 파이프라인을 만든다.

- ETL·ELT 파이프라인 구축
- 데이터 웨어하우스와 데이터 레이크 운영
- 배치·스트리밍 데이터 처리
- 데이터 품질과 카탈로그 관리

### 데이터 분석가 (Data Analyst)

데이터를 이용해 비즈니스 질문에 답하고 의사결정을 돕는다. SQL, 스프레드시트, BI 도구를 사용해 지표를 정의하고 대시보드와 분석 보고서를 만든다.

### 데이터 사이언티스트 (Data Scientist)

통계와 머신러닝으로 예측 모델을 만들거나 실험을 설계한다. 회사에 따라 분석가에 가까울 수도 있고 머신러닝 연구자에 가까울 수도 있다.

### 머신러닝 엔지니어 (ML Engineer)

머신러닝 모델을 실제 서비스에서 안정적으로 동작하게 만든다. 모델 학습뿐 아니라 서빙, 성능 최적화, 모니터링, 재학습 파이프라인을 담당한다.

### DBA (Database Administrator)

데이터베이스의 안정성, 성능, 보안과 복구 가능성을 책임진다.

- 데이터베이스 설치, 설정, 버전 업그레이드
- 백업·복구와 재해 복구 체계 운영
- 쿼리 튜닝, 인덱스와 용량 관리
- 복제, 고가용성, 접근 권한과 감사 관리

개발자가 애플리케이션 관점에서 테이블과 쿼리를 만든다면 DBA는 조직 전체의 데이터베이스를 장기적으로 안전하게 운영하는 데 초점을 둔다. 클라우드와 관리형 DB가 보편화되면서 일부 회사에서는 이 역할을 플랫폼 엔지니어나 SRE가 함께 담당하기도 한다.

## 3. 인프라와 안정성을 담당하는 직무

### DevOps 엔지니어

개발과 운영 사이의 자동화와 협업 체계를 개선한다. CI/CD, Infrastructure as Code, 컨테이너, 모니터링 환경을 구축해 소프트웨어가 빠르고 반복 가능하게 배포되도록 돕는다.

DevOps는 본래 문화와 업무 방식에 가까운 말이지만, 국내외 채용 시장에서는 관련 플랫폼과 자동화를 담당하는 직무명으로도 사용된다.

### SRE (Site Reliability Engineer)

소프트웨어 엔지니어링 방식으로 서비스 신뢰성 문제를 해결한다.

- SLI, SLO, 에러 버짓 정의
- 모니터링, 알림, 장애 대응과 사후 분석
- 반복 운영 업무 자동화
- 용량 계획과 성능 개선

DevOps 엔지니어와 업무가 겹치지만 SRE는 특히 **측정 가능한 신뢰성 목표와 운영 자동화**를 강조한다.

### 클라우드·플랫폼 엔지니어 (Cloud/Platform Engineer)

개발팀이 인프라를 직접 쉽고 안전하게 사용할 수 있도록 공통 플랫폼을 만든다. Kubernetes, 클라우드 계정, 배포 시스템, 개발자 포털, 공통 관측 도구 등을 제공한다.

### 시스템·네트워크 엔지니어

서버, 운영체제, 사내 네트워크, 방화벽, 로드 밸런서와 같은 기반 환경을 구축하고 운영한다. 온프레미스 데이터센터의 비중이 큰 조직에서 역할이 더욱 뚜렷하다.

### 보안 엔지니어 (Security Engineer)

애플리케이션, 인프라, 네트워크와 조직의 정보를 공격으로부터 보호한다. 세부적으로 애플리케이션 보안, 클라우드 보안, 침해 대응, 보안 관제, 모의 해킹, 보안 거버넌스 등으로 나뉜다.

## 4. 고객의 기술 문제를 해결하는 직무

### FDE (Forward Deployed Engineer)

고객 현장 또는 고객과 가까운 위치에서 자사 제품을 고객 환경에 맞게 적용하고, 필요한 기능까지 직접 개발해 문제를 해결한다.

- 고객의 업무와 기술 환경 파악
- 제품 설치, 통합, 데이터 연결과 맞춤 개발
- 짧은 주기의 프로토타입 제작과 피드백 반영
- 현장에서 발견한 요구사항을 제품팀에 전달

일반 제품 개발자보다 고객 접점이 많고, 컨설턴트보다 직접 코드를 작성하는 비중이 높다. 불명확한 요구사항을 구조화하는 능력, 빠른 구현력, 커뮤니케이션 능력이 모두 중요하다.

> 일부 회사는 FDE와 유사한 역할을 Forward Deployed Software Engineer, Field Engineer, Customer Engineer 또는 Deployment Strategist 등으로 부른다.

### SA (Solutions Architect 또는 System Architect)

SA는 회사와 산업에 따라 의미가 크게 달라진다.

#### Solutions Architect

고객 요구사항을 분석해 자사 제품이나 클라우드를 조합한 기술 해결책을 설계한다.

- 요구사항과 제약 조건 분석
- 시스템 구성도, 데이터 흐름, 보안과 비용 설계
- 기술 검증(PoC)과 제안 지원
- 개발팀, 영업팀, 고객 기술팀 사이의 조율

대개 직접 제품 전체를 개발하기보다 올바른 구조와 도입 방향을 제시한다. 클라우드 회사나 B2B 솔루션 회사에서 흔히 볼 수 있다.

#### System Architect

조직 내부 또는 프로젝트 전체 시스템의 구조와 기술 원칙을 설계한다. 확장성, 가용성, 보안, 시스템 간 인터페이스와 기술 표준에 더 초점을 둔다.

채용 공고에서 SA를 봤다면 두 의미 중 어느 쪽인지 반드시 확인해야 한다.

### Sales Engineer·Pre-sales Engineer

영업 과정에서 기술 전문성을 제공한다. 데모, 기술 질의응답, PoC, 제안서와 기술 검토를 담당하며 고객의 구매 결정을 돕는다. 매출 목표와 연결되는 경우가 많다는 점이 SA나 FDE와의 주요 차이다.

### Technical Account Manager (TAM)

제품을 도입한 주요 고객이 장기적으로 제품을 잘 사용하도록 돕는다. 기술 지원, 장애 조율, 운영 상태 검토, 활용 계획 수립을 담당한다. 일반 기술 지원보다 고객 관계와 선제적 관리의 비중이 크다.

### Developer Relations (DevRel)·Developer Advocate

개발자를 고객으로 삼는 제품의 사용 경험과 커뮤니티를 개선한다. 기술 콘텐츠, 예제, 발표, 행사, 사용자 피드백 수집을 담당하며 코드 작성 능력과 설명 능력이 함께 필요하다.

## 5. 품질과 개발 과정을 지원하는 직무

### QA 엔지니어 (Quality Assurance Engineer)

제품이 요구사항을 충족하고 안정적으로 동작하는지 검증한다. 테스트 계획, 수동 테스트, 결함 관리, 출시 품질 판단을 담당한다.

### SDET·테스트 자동화 엔지니어

테스트 가능한 구조와 자동화 도구를 코드로 만든다. 단위·통합·E2E 테스트 체계, 테스트 데이터, 성능 테스트와 CI 연동 등을 담당한다.

### 소프트웨어 아키텍트 (Software Architect)

대규모 소프트웨어의 구조, 모듈 경계, 기술 선택과 품질 속성을 설계한다. 별도의 직책일 수도 있고 시니어·스태프 엔지니어가 수행하는 역할일 수도 있다.

### 테크니컬 라이터 (Technical Writer)

API 문서, 개발자 가이드, 튜토리얼과 제품 설명서를 작성하고 문서 체계를 관리한다. 기술을 정확히 이해하면서 독자의 관점으로 쉽게 설명하는 능력이 중요하다.

## 6. 직무를 비교하는 기준

| 직무 | 주된 대상 | 핵심 결과물 | 고객 접점 | 코딩 비중 |
| --- | --- | --- | --- | --- |
| 제품 개발자 | 자사 서비스 사용자 | 제품 기능 | 낮음~중간 | 높음 |
| FDE | 특정 기업 고객 | 고객 환경에 적용된 해결책 | 매우 높음 | 높음 |
| Solutions Architect | 도입 예정·진행 고객 | 아키텍처와 도입 방안 | 높음 | 낮음~중간 |
| DBA | 조직의 데이터베이스 | 안정적이고 빠른 DB 환경 | 낮음 | 중간 |
| DevOps·플랫폼 엔지니어 | 내부 개발팀 | 배포·인프라 플랫폼 | 낮음 | 중간~높음 |
| SRE | 서비스와 사용자 | 신뢰성, 자동화, 장애 감소 | 낮음 | 높음 |
| Sales Engineer | 구매 검토 고객 | 데모, PoC, 기술 제안 | 매우 높음 | 낮음~중간 |
| QA·SDET | 제품과 개발팀 | 품질 기준과 테스트 체계 | 낮음 | 직무에 따라 다름 |

코딩 비중만으로 직무의 기술 난이도를 판단할 수는 없다. 아키텍처 설계, 운영 책임, 고객 문제의 불확실성처럼 서로 다른 종류의 기술적 난도가 존재한다.

## 7. 채용 공고에서 확인할 질문

- 이 직무가 최종적으로 책임지는 결과는 무엇인가?
- 신규 개발, 기존 시스템 운영, 고객 대응의 비율은 각각 어느 정도인가?
- 직접 코드를 작성하고 배포하는가?
- 온콜이나 야간 장애 대응이 있는가?
- 특정 고객을 위한 개발이 제품 본체에 합쳐지는가, 별도로 유지되는가?
- 성과를 기능 출시, 안정성, 고객 만족, 매출 중 무엇으로 평가하는가?
- 같은 직무의 구성원과 성장 경로가 존재하는가?

직무 선택에서는 이름보다 하루 동안 실제로 하는 일, 협업 대상, 평가 기준이 자신의 강점과 선호에 맞는지를 보는 것이 중요하다.
